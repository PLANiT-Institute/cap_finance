# L6 · 코드·재현 (2026-09-11 08:55 KST)

관점: v2.2의 가격·회계 규약으로 후보 생성(E2)부터 다시 돌려 "구 수소가에서 생성된 메뉴"라는 L3의 유보를 없애고, 감사에서 지적된 코드 결함(gap 미기록, retire 목적함수, 테스트 스위트, E2의 할당 처리)을 고친다.

## E2 재생성 (v2.3)

설정: v2.2(구조적 수소가, KAU 2026 앵커, 순거래 무상할당=예산경로) + 실질 무위험 할인율 2.4%(L5) + frontier 6점·30초·gap 2%·단일 스레드·조기폐쇄 미허용. E1→E2 실행 20.3분(철강 조합당 4.5분, 석화 1.2분). 재생성 메뉴는 27개 일정(v1 동결 45개는 배출 방향 확장 포함), 계약 변형 270개.

재실행 중 발견한 결함 둘. E2가 무상할당 경로를 시나리오 없이 호출해 순거래 모드에서 실패했고(v2.1·v2.2는 E2를 재사용해 드러나지 않았다), v2 보정에서 수소 σ가 NaN이라 대리위험 항이 곱셈 오류를 냈다. 전자는 시나리오를 넘기도록, 후자는 대리위험의 수소 σ를 전력 σ(구조적 상한)로, 탄소 항을 추정 KAU σ × 순의무(E−A)로 바꿔 생성기의 위험 개념을 평가기(ES_abs)와 같은 방향으로 맞췄다(감사 7번). 건설비 σ는 0.

결과는 v2.2를 2.4%로 재평가한 것과 거의 같다. 평균 최소 일정의 기술 구성은 동일(철강 eff+H₂-DRI(+HyREX), 석화 e-cracker만), MCI·NSC는 E2가 바른 가격에서 약간 싼 일정을 찾았다(MCI B20 3,803→2,170, NZ15 3,152→2,412; NSC B20 92,461→89,839, NZ15 74,509→73,530 십억원). POSCO NZ15 ΔES₉₀ −43,470→−45,255. 경계 위 기술 일정은 POSCO NZ15 3개, MCI NZ15 2개, 나머지 1개. 즉 L3의 "구 메뉴 때문에 결과가 다를 수 있다"는 유보는 이 사례에서는 작았다.

## 코드 변경

`e2_milp.py`: CBC 로그를 임시 파일로 받아 실제 상대 gap과 하한을 `plan_index.csv`의 `mip_gap_actual`·`mip_lower_bound`에 기록한다. 27개 해 중 13개에서 파싱됐고(평균 0.54%, 최대 1.0%), 나머지 14개는 CBC가 전처리에서 끝내 하한 줄을 찍지 않아 NaN이다 — "기록 불가"로 남긴다. `config.py`: `CAP_CONFIG` 환경변수로 규약 파일을 고정할 수 있다. `tests/conftest.py`: 세션 기본을 `config_legacy.yaml`로 고정 — data/sample 위의 기존 테스트는 과거 규약을 검사하는 것이므로. 루트 `config.yaml`: 할인율 2.4%(무위험 실질)로, `retire_max_share` 주석에 "연구 사례는 0(조기폐쇄 미허용) — 허용 시 마진만 잃는 목적함수 탓에 전량 폐쇄가 최적이 되는 결함(감사 B2)" 명시. `scripts/expand_candidates_inplace.py`: 배출 방향 확장을 재생성 메뉴에 적용하는 독립 스크립트.
