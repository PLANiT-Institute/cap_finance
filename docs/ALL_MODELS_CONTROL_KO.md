# 통합 Excel 전체 재계산

통합 파일 v6에서는 저장한 파일 한 개로 `Control`, `NCC cash`, `Timing`의 세 분석을 함께 갱신할 수 있다.

1. 원하는 분석의 노란 입력 셀을 바꾸고 파일을 저장한다.
2. **“이 파일의 세 분석을 전체 재계산해 줘”**라고 요청한다.
3. 새 결과 파일에서 세 분석의 ‘최신 계산’ 표시와 입력 가정을 확인한다. Timing은 후보별 ‘적격/불가’와 효율경계를 함께 확인한다.

이 과정은 프로젝트 계산기를 호출한다. Excel에서 값을 바꾸기만 하면 새 몬테카를로가 실행되는 매크로 방식은 아니다. 입력 변경 중에는 이전 결과가 ‘재계산 필요’로 표시된다.

## 함께 실행하는 것과 합산하는 것의 차이

세 분석은 서로 다른 질문과 원장을 유지한다. 각 시나리오·경로 수·시드·할인율을 해당 입력에서 읽으며 임의로 하나의 값으로 덮어쓰지 않는다. 동일한 시나리오 비교를 원하면 각 분석의 입력을 맞춰야 한다. 시나리오 이름과 시드가 같더라도 공정·가격·생산·화폐 단위가 다르면 하나의 기업 비용으로 합산할 수 없다.

- **Control:** 구매전력·나프타·메탄의 부분 운영비 비교. EUR2024 기준 입력과 원화 환산 가정을 사용한다.
- **NCC cash:** 문헌 공정의 건설·갱신·유지비를 포함한 현금비용 비교. EUR2019 기준의 별도 참조 가정이다.
- **Timing:** 기존 설비 유지 대비 네 전환 시점의 배출 자격과 비용 비교. 고정 참조 생산량·가격식 아래의 평균–ES 후보 경계이며 TCaR도 병기한다.

Timing에서 적격 후보가 없으면 해당 분석은 새 가격 표본을 만들지 않고 비용을 ‘불가’로 표시한다. 다른 두 분석은 각자 정의한 참조 비교를 갱신할 수 있다. 그 값이 Timing의 감축 제약까지 만족한다는 뜻은 아니다.

## 실패했을 때

세 입력과 공유 원문 값·단위를 먼저 검사한다. 입력 셀의 수식, 빈칸, 범위 초과 또는 원문 패키지 변경을 발견하면 새 결과를 내보내지 않는다. 계산·저장 수식 대조 중 오류가 발생하거나 실행 도중 원본 입력이 바뀌어도 요청한 결과 파일을 발행하지 않는다. 기존 입력과 기존 결과 파일을 덮어쓰지 않는다.

각 단계의 검증 자료를 별도 실행 폴더에 보존한다. 전체 완료 기록은 세 분석의 결과·입력 대조와 새 파일 발행이 끝난 뒤 남긴다. 중간 두 분석의 성공만으로 전체 완료라고 표시하지 않는다.

## 상세 설명과 실행 환경

각 입력의 의미와 고정 가정은 [공동 가격·부분 비용 안내](JOINT_RESEARCH_CONTROL_KO.md), [NCC 현금비용 안내](NCC_CASH_CONTROL_KO.md), [전환 시점 안내](TIMING_CONTROL_KO.md)를 참조한다. 실제 기업의 구매계약이나 장기 꼬리분포가 보정된 도구는 아니며, Microsoft Excel 앱에서의 직접 실행 검증은 남아 있다.

개발 재현 명령은 프로젝트 Python으로 `scripts/all_models_workbook_control.py --input <저장한입력.xlsx> --output <새결과.xlsx> --scratch <빈실행폴더>`다. 현재 데스크톱의 번들 Node와 Artifact Tool을 사용하며 다른 환경의 런타임 설정은 별도 작업이다. 부분 갱신용 기존 계산기도 유지한다.
